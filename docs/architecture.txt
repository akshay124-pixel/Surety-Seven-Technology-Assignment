```
## Data Flow: Happy Path

1. Client → POST /applications → API
2. API → Check idempotency → PostgreSQL
3. API → Create application (PENDING) → PostgreSQL
4. API → Enqueue job → Redis/BullMQ
5. API → 201 Created → Client

   [Client can now GET status while processing continues]

6. Worker → Dequeue job → Redis/BullMQ
7. Worker → Update (EVALUATING) → PostgreSQL
8. Worker → GET applicant → External Applicant API
9. Worker → Calculate score → UnderwritingEngine
10. Worker → BEGIN TX → PostgreSQL
11. Worker → Update (APPROVED) → PostgreSQL
12. Worker → Insert factors → PostgreSQL
13. Worker → Insert outbox event → PostgreSQL
14. Worker → COMMIT TX → PostgreSQL
15. NotificationWorker → Poll outbox → PostgreSQL
16. NotificationWorker → POST event → External Downstream API
17. NotificationWorker → Mark DELIVERED → PostgreSQL


## Reliability Patterns

┌─────────────────────────────────────────────────────────────┐
│ Pattern: Idempotency                                        │
├─────────────────────────────────────────────────────────────┤
│  Request 1 (key=X, hash=H1)                                 │
│    → Check DB → Not found → Process → Store (X, H1, app1)  │
│                                                             │
│  Request 2 (key=X, hash=H1)                                 │
│    → Check DB → Found (X, H1, app1) → Return cached app1   │
│                                                             │
│  Request 3 (key=X, hash=H2)                                 │
│    → Check DB → Found but hash differs → 409 Conflict      │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ Pattern: Outbox                                             │
├─────────────────────────────────────────────────────────────┤
│  BEGIN TRANSACTION                                          │
│    ├─ UPDATE applications SET status='APPROVED'             │
│    ├─ INSERT decision_factors (...)                         │
│    └─ INSERT outbox_events (eventId, payload, status)      │
│  COMMIT                                                     │
│                                                             │
│  [Decision and outbox event are atomic]                     │
│                                                             │
│  Later: Worker polls outbox, sends event, marks DELIVERED   │
│                                                             │
│  [If worker crashes, event remains for retry]               │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ Pattern: Retry with Exponential Backoff                     │
├─────────────────────────────────────────────────────────────┤
│  Attempt 1: immediate     → Timeout                         │
│  Attempt 2: wait ~2s      → 500 Error                       │
│  Attempt 3: wait ~4s      → Success                         │
│                                                             │
│  Non-retryable errors (malformed response, 404):            │
│    → Mark FAILED immediately, don't retry                   │
└─────────────────────────────────────────────────────────────┘
```

## State Machine

```
Application Lifecycle States:

    [Client submits]
           │
           ▼
      ┌─────────┐
      │ PENDING │ ◄─── Initial state after POST
      └────┬────┘
           │
           │ [Worker picks up job]
           │
           ▼
    ┌────────────┐
    │ EVALUATING │ ◄─── Fetching applicant data, scoring
    └─────┬──────┘
          │
          │ [Based on score]
          │
    ┌─────┼─────┬─────────┐
    │     │     │         │
    ▼     ▼     ▼         ▼
┌────┐ ┌────┐ ┌────┐ ┌──────┐
│APP-│ │REF-│ │DEC-│ │FAILED│ ◄─── All terminal states
│ROVE│ │ERRE│ │LINE│ │      │      (no transitions out)
│D   │ │D   │ │D   │ │      │
└────┘ └────┘ └────┘ └──────┘

Score >= 80 → APPROVED
Score 50-79 → REFERRED
Score < 50  → DECLINED
Error       → FAILED
```
